UX / UI 优化方案

系统设置页 · 布局与使用优化方案

针对 ui/src/views/SettingsView.vue 及其 8 个配置子页面的信息架构、栅格布局、操作流与无障碍体验进行审查，提出分级、可落地的改进建议。

对象：设置页（/admin/settings） 范围：布局 + 使用（review） 状态：方案 B 已实施
实施记录
  • 已重构为侧栏分节导航（5 组 10 面板），替代原 8 个平级 Tab。
  • 已落地页面脏标记 + 顶部未保存提示 + 离开路由拦截；重置与保存按钮在无更改时禁用。
  • 已落地危险操作二次确认：数据库驱动切换保存前强制弹窗。
  • 原 SettingsBasic 拆分为 应用共享目录 / 私有与临时文件 / 上传配置 三个面板。
  • LDAP 卡收敛为折叠块；各子页 field-hint 统一为 AA 对比度次级文字色。
  • 构建已验证通过（yarn build，Vite 输出 SettingsView / el-menu-item / el-collapse-item 分块）。

02 审查发现

分「布局」「使用与交互」「一致性」「无障碍」四类，按影响标记 P1（高）/ P2（中）/ P3（低）。

布局类

级别问题说明
P18 个顶级 Tab 信息量失衡「基本信息」一页承载 6 张卡片（应用/共享目录/私有/临时/上传/URL），而「存储配置」仅 3 个字段、单卡。平级 Tab 造成层级感混乱，导航负担重。
P1底部「重置 / 保存」为全局语义操作栏固定浮底，但设置分散在 8 个 Tab 内；用户在此页其它 Tab 改动后，需回到底部才知是否已提交，缺乏「当前页是否脏」的可见反馈。
P2关键条目缺分组「基本信息」内的 6 张卡片彼此主题差异大（应用名 vs URL 上传网段），缺少二级分组或分区标题，扫读成本高。
P3移动端双列栅格塌缩el-col :span="12" :xs="24" 已正确单列化；但卡片内字段提示与操作未针对窄屏做收尾衔接（如小写提示、按钮换行）。整体受 AdminLayout 侧栏影响，窄屏体验一般。

使用与交互类

级别问题说明
P1无「未保存」提示与离开拦截用户改动后直接切换 Tab 或离开页面，数据易丢失；「重置」无二次确认，误点即回退未保存改动。
P1危险操作缺防护数据库切换、保存等一旦提交即改动运行配置；数据库页虽有警示 Alert，但「保存」按钮无区分，缺少关键项二次确认（如改动 DB 驱动时提醒需重启）。
P2保存成功反馈弱仅 Toast 提示；服务器地址变更后引导跳转较绕，其它需重启的服务协议（FTP/FTPS/WebDAV）改动后无「需重启生效」说明。
P2表单校验不完整部分字段仅有 placeholder / hint，缺即时校验或提交前校验（端口冲突、DSN 格式、Cron 表达式合法性等）。
P3「LDAP 认证」为占位卡该卡片仅一条提示「暂未提供界面配置」且不可操作，占导航/内容空间，可用性价值低。

一致性 / 工程类

级别问题说明
P2提示样式重复定义每个子页都重复声明 .field-hint、.el-card:hover 盒阴影（8 处副本）；应抽为全局工具类或卡片组件，减少漂移。
P2label 宽度不统一子页 label-width 混用 100/120/140px，块槽出现不对齐；应统一为单一 token。
P3单位输入自维护逻辑文件大小用「文本 + 解析」实现，分散在各 computed；有现成 NumberUtils.parseFileSize，但可在交互上提供单位下拉/格式化实时回显，提升准确性。

无障碍与可访问性

级别问题说明
P1提示文字对比度不足.field-hint 统一 12px 且用 --el-text-color-placeholder（偏浅），在中灰底上对比度 < 4.5:1，弱视用户难读；字段说明不应使用「占位灰」。参考项目 WCAG AA 约定。
P2键盘聚焦 / 焦点环一致性项目有 @focus-ring token，但设置页表单/开关未统一套用可见焦点状态（Element 默认有，但自定义卡片 hover 无对应 focus-visible）。
P3Tab 切换动画 / 语义无 aria-live 播报保存结果；Tab 切换建议用 role="tabpanel" 明确语义（Element 默认符合，但保存反馈建议补 aria）。

04 落地建议清单

按优先级给出可执行改动，标注影响范围与工作量。

1
引入「页面脏标记」+ 离开拦截 P1
保存成功后快照 settings 为 baseline；任意字段变更对比出差异，在 Tab 标签与按钮上显示脏标记（●），切换页/离页时 beforeRouteLeave 弹确认。改动集中在 SettingsView.vue，子页无需改。
2
危险操作二次确认 P1
保存前对比 baseline：若 database.driver 变更 → 强制确认「切换数据库需重启，请确认数据已迁移」；TLS/证书、服务端口变更 → 提示需重启。
3
统一与抽取公共样式 P2
把 8 份重复的 .field-hint、.el-card:hover 收敛为全局 settings 工具类或封装 SettingCard；提示文字改用 @text-color-secondary（AA）而非 placeholder，统一 label 宽度为单一 token。
4
分组 Tab，压缩导航 P2
将「基本信息」的 6 卡按 基础/存储/上传 拆分；Tab 收敛为 5~6 个（如 基础信息、服务、存储与上传、预览与MIME、数据库、安全、资源）。MIME 属预览域，可并入「预览」。
5
移除 / 收敛占位卡 P3
「LDAP 认证」无可操作项，可并入「访问控制」页顶部的说明折叠块，而非独立卡片。其他单字段页同理合并。
6
移动端与表单校验收尾 P3
窄屏下卡片内 hint 换行、按钮全宽；补充 Cron / 端口 / DSN 在提交时的 el-form 校验规则与即时错误回显。
建议推进方式：先落地 P1 两项（脏标记 + 危险确认），价值最高、改动面小；P2 的样式收口与 Tab 重组可作为第二阶段统一重构，顺带解决无障碍对比度问题。可先用「方案 A」原型试用，再决定是否演进到「方案 B」侧栏布局。
