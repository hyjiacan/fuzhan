# 第三方认证与本地账号隔离方案（v2）

- 日期：2026-11-18
- 状态：待评审
- 范围：后端登录链路、用户/认证关联模型、管理端用户页、配置校验
- 前提：**不支持 LDAP 与 OAuth2/OIDC 同时启用**，继续保持二选一

## 版本历史

| 版本 | 变更 |
|---|---|
| v1 | 初版：严格路由、外部 ID 绑定、冲突裁决、孤儿账号、凭证隔离 |
| v2 | 依据线上现状（无 OAuth2、无 LDAP 同名冲突）简化迁移；修正迁移顺序与唯一索引实现；新增只读预检 SQL、`identity_state` 派生状态、provider 稳定标识；明确登录日志失败语义 |

## 0. 线上现状与结论

已确认：

- 线上**未启用 OAuth2/OIDC**，`auth_records` 中不存在 `auth_type='oauth2'` 的记录。
- LDAP 已启用，但当前**不存在本地用户与目录用户同名**的情况。

由此：

- v1 中“历史 OAuth2 同名绑定导致回填锁号”的风险不成立，迁移可简化为“LDAP 记录 → ldap，其余 → local”。
- 严格路由切换的实际行为变化只有一条：本地账号不再尝试 LDAP，风险低。
- 冲突拒绝与绑定/转本地能力仍需实现，作为后续启用 OAuth2 的前置条件。
- OAuth2 相关改造可以在本方案中一并完成，但不随本次发布启用。

## 1. 背景与问题

当前系统支持本地账号、LDAP、OAuth2/OIDC 三种登录方式。LDAP 与 OAuth2 的配置、服务、路由相互独立，但管理界面通过一个下拉框强制二选一（[SettingsAuth.vue](../../../ui/src/views/settings/SettingsAuth.vue)）。

登录链路采用“LDAP 优先、失败回退本地密码”的机会式认证，并按用户名查找/复用本地用户，由此产生：

| 编号 | 问题 | 现状 |
|---|---|---|
| P1 | LDAP 失败无条件回退本地密码 | 目录侧禁用/删除/改密策略无法真正生效，本地密码成为“影子凭证” |
| P2 | 本地用户登录也要先连目录 | LDAP 不可达时本地用户需等待建连超时；本地凭据也会被发给目录 bind |
| P3 | 同名用户静默合并 | LDAP 同名账号可直接进入已有本地账号（含管理员），无告警、无裁决 |
| P4 | OAuth2 也按用户名静默绑定 | 与 LDAP 行为不一致；不同人的同名账号会共用账号 |
| P5 | 用户来源不可见、不可筛选 | 用户列表无来源列，接口只有 `query` 参数 |
| P6 | 本地注册与管理员创建无法区分 | 两者都无外部关联记录、都有本地密码 |
| P7 | 停用 LDAP 后 JIT 用户被锁死 | 账号既不能登录，也没有待处理视图和处置入口 |
| P8 | 登录日志来源失真 | LDAP 登录在 `login_logs.method` 中记为 `local` |
| P9 | 管理员重置密码会制造影子凭证 | 对外部认证用户直接写 `password_hash`，但不改变认证归属 |
| P10 | 互斥只在前端 | 后端配置保存无互斥校验，改 YAML 或直接调 API 仍可同时启用 |

## 2. 目标与非目标

### 2.1 目标

1. 认证路径由账号归属决定（deterministic），取消“先试一个、失败再试另一个”。
2. 外部身份按 `(provider, external_id)` 绑定，用户名只作展示。
3. 同名冲突显式拒绝并留痕，由管理员裁决，不再静默合并。
4. 用户管理页可查看来源、按来源与身份状态过滤。
5. 停用认证源后，账号进入可处置的待处理状态。
6. 外部账号与本地密码凭证隔离。
7. 登录审计能还原真实认证源。
8. 前后端同时保证 LDAP / OAuth2 二选一。

### 2.2 非目标

- 不支持 LDAP 与 OAuth2 同时启用。
- 不做目录用户删除的自动回收（SCIM 式 deprovision）。
- 不做 OIDC 组/角色映射、多租户、多 LDAP 实例。
- 不自动合并历史同名账号；本方案上线时也不存在此类数据。
- 不做孤儿账号的批量接口（当前账号量下逐个处置足够，预留后续扩展）。

## 3. 设计原则

| 原则 | 业内参考 | 本方案落地 |
|---|---|---|
| 身份绑定使用 `(provider, external_id)` | Keycloak Federated Identity、GitLab `identities.extern_uid`、Gitea `login_source` | `auth_records` 唯一绑定，provider 使用稳定标识 |
| 认证源由账号决定，默认 fail-closed | Authelia、Keycloak、GitLab LDAP 模式 | `users.auth_source` 路由；本地账号绝不尝试 LDAP |
| 同名冲突拒绝并人工裁决 | Keycloak first broker login | 通用失败提示 + 安全事件 + 管理员绑定/转本地 |
| JIT 供给 + 状态同步 | Okta/Entra JIT | 仅“本地不存在且无同名冲突”时 JIT |
| 停用即冻结，不自动删除 | 主流 IdP deprovision | 派生 `identity_state`，提供转本地/禁用/删除 |
| 凭证隔离 | GitLab/Nextcloud LDAP 用户不存本地密码 | 外部账号 `password_hash` 恒为空 |

## 4. 目标模型

### 4.1 数据模型

#### 4.1.1 `users` 新增字段

文件：[user.go](../../../server/internal/models/user.go)

```go
type User struct {
    // ...现有字段...
    // AuthSource 账号归属认证源：local / ldap / oauth2
    AuthSource string `gorm:"size:16;not null;default:local;index:idx__users__auth_source" json:"auth_source"`
    // CreatedVia 账号创建渠道：self_register / admin_create / ldap_jit / ldap_sync / oauth2_jit / legacy
    CreatedVia string `gorm:"size:20;not null;default:legacy" json:"created_via"`
}
```

- `auth_source` 决定认证路由，只能由管理员绑定/转换操作改变；登录行为不会自动改变它。
- `created_via` 表示首次创建渠道，**创建后不可变**，只用于展示与筛选。
- `disabled` 继续表示管理员禁用；认证源停用是派生状态，不写库。

#### 4.1.2 `auth_records` 与 provider 稳定标识

文件：[api_key.go](../../../server/internal/models/api_key.go)

- 绑定键为 `(auth_type, provider_name, external_id)`，增加唯一索引 `idx__auth_records__auth_type_provider_name_external_id`。
- `provider_name` 语义固定为 **provider key**，不再使用会变化的主机名/签发方：
  - LDAP：固定为 `"ldap"`（系统只支持一个 LDAP 目录）。
  - OAuth2：使用新增配置 `auth.oauth2.provider_id`（启用时必填，例如 `keycloak-prod`），存储为 `oauth2:<provider_id>`。
- `provider_name` 只用于绑定，不作为界面展示名；展示名继续使用 `auth.oauth2.provider_name`。
- `external_id`：LDAP 为 DN，OAuth2 为 `sub`。

新增配置项：

```yaml
auth:
  oauth2:
    provider_id: keycloak-prod   # 稳定标识，启用时必填；变更视为认证源迁移
```

#### 4.1.3 状态派生：`identity_state`

不新增“孤儿”字段，读取时派生：

| `identity_state` | 判定 | 含义 |
|---|---|---|
| `ok` | 认证源启用且绑定 provider 匹配 | 正常 |
| `orphaned` | 认证源未启用或配置不完整 | 认证源已停用 |
| `provider_mismatch` | 存在绑定记录的 provider 与当前 provider key 不一致 | 认证源被替换过 |
| `inconsistent` | 违反 §4.2 不变量（source 与记录不符） | 数据异常，需修复 |

优先级：`inconsistent` > `provider_mismatch` > `orphaned` > `ok`。

### 4.2 数据不变量

必须始终成立：

1. `auth_source != local` ⇔ 至少一条 `auth_records`，且 provider 与当前配置一致。
2. `auth_source == local` ⇒ 无 `auth_records`，且 `password_hash != ''`。
3. `(auth_type, provider_name, external_id)` 全局唯一。
4. `password_hash == ''` ⇔ `auth_source != local`。
5. `created_via` 创建后不变。

实现要求：

- 创建、绑定、转本地、删除均在**同一事务**内完成。
- 启动时执行一致性审计，违规账号写日志并在管理端标记 `inconsistent`。
- 应用层写入前做唯一性检查；唯一索引作为最终兜底。

### 4.3 认证路由

改造点：[auth_service.go](../../../server/internal/services/auth_service.go) 的 `LoginByPassword`。

处理顺序：

1. 按 `username` 查询本地用户（先精确匹配，再 `LOWER(username)` 匹配，避免大小写产生重复账号）。
2. **已存在**：按 `auth_source` 路由。
   - `local`：只校验本地密码，**不连接 LDAP**。
   - `ldap`：只走 LDAP；认证源未启用或不可达直接失败，不回退本地密码。
   - `oauth2`：拒绝密码登录，返回通用提示。
3. **不存在**：
   - LDAP 启用且允许自动建号 → 走 LDAP，成功后 JIT 建号；
   - 否则返回通用登录失败。

路由矩阵：

| 本地账号 | 密码表单登录 | OAuth2 按钮 |
|---|---|---|
| 不存在 | LDAP 启用则尝试 LDAP 并 JIT；否则失败 | 按 OAuth2 流程 JIT |
| `local` | 仅本地密码 | 无同名冲突时允许，冲突则拒绝 |
| `ldap` | 仅 LDAP；源不可用即失败 | 不允许（除非管理员显式绑定） |
| `oauth2` | 拒绝，提示使用统一认证 | 仅允许同一 provider + subject |

可用性说明：

- 本地管理员账号（`auth_source=local`）作为 break-glass 入口，不参与外部认证。
- 本方案不提供 LDAP 故障时自动回退本地密码。若未来确有需要，只允许新增显式配置 `auth.ldap.fallback_to_local`（默认 `false`），且仅在“目录不可达”时生效。

### 4.4 账号关联与冲突裁决

#### 4.4.1 LDAP

改造点：[ldap.go](../../../server/internal/auth/ldap.go) 的 `findOrCreateUser`、`SyncUsers`。

1. 目录认证成功后，先按 `(auth_type=ldap, provider_name="ldap", external_id=DN)` 查绑定。
   - 命中 → 返回对应用户；若目录用户名已变化，尝试更新本地用户名（无冲突时），否则拒绝并记录。
2. 未命中时按用户名查本地用户（精确 + 大小写不敏感）：
   - 不存在 → `auto_create_user` 开启则创建（`auth_source=ldap`、`created_via=ldap_jit|ldap_sync`）并写绑定；关闭则拒绝。
   - 已存在且 `auth_source=ldap` 且 provider 匹配 → 视为历史用户，补齐绑定后登录。
   - 已存在但 `auth_source=local` / `oauth2`，或 provider 不匹配 → **拒绝登录**，写安全事件 `auth.identity_conflict`，不改任何字段。
3. `SyncUsers` 遇到同名冲突时跳过并计数，单轮聚合告警，不再“补写姓名后视为已有”。
4. 历史 LDAP 用户（空密码、无绑定）在首次成功登录时补齐绑定。

#### 4.4.2 OAuth2

改造点：[oauth2.go](../../../server/internal/auth/oauth2.go) 的 `findOrCreateUser`。

1. 先按 `(oauth2, provider_id, subject)` 查绑定，命中即返回。
2. 未命中时按用户名查本地用户：
   - 不存在 → `auto_create_user` 开启则创建（`auth_source=oauth2`、`created_via=oauth2_jit`）并写绑定；关闭则拒绝。
   - 已存在 → **拒绝**，写 `auth.identity_conflict`，不再走“同名即绑定”。
3. 删除自动加后缀的 `uniqueUsername` 逻辑，冲突不再被隐藏成新账号。
4. 启用前必须确认 `username_claim` 唯一；若 IdP 的 `preferred_username` 不唯一，应改用 `email` 或 `sub` 派生本地用户名。

#### 4.4.3 管理员裁决

- **绑定外部身份**：把一个外部身份绑定到指定用户，适用于确认是同一人。
- **转为本地**：设置新密码、删除全部绑定、`auth_source=local`，适用于保留数据但不再使用外部认证。
- 不提供“裸解绑”：解绑会留下既无密码又无绑定的不可登录账号。需要纠正错误绑定时，先“转本地”再重新“绑定”。
- 所有操作写操作日志，记录原 `auth_source` 与 provider。

### 4.5 生命周期

停用 LDAP 后：

1. 用户与绑定记录保留，不批量删除、不改源。
2. 派生 `identity_state=orphaned`。
3. 登录返回“账号当前不可用，请联系管理员”，不暴露认证源。
4. 用户页可按 `identity_state` 过滤，并提供转本地、禁用、删除。
5. 重新启用且 provider 未变化时，状态恢复 `ok`，绑定继续有效。

目录侧单个用户被删除/禁用时，本地不自动处理；登录失败会暴露问题。自动 deprovision 列入后续独立方案。

### 4.6 凭证隔离

- 外部账号 `password_hash` 恒为空。
- 管理员对非本地账号执行“重置密码”时拒绝，提示先“转为本地账号”。
- 用户自助改密、自助注销按 `auth_source` 判断，不再依赖“密码是否为空”。
- 绑定外部身份时清空本地密码；转本地时写入新密码并删除绑定。

### 4.7 审计

1. `login_logs.method`：
   - 成功：记录真实来源 `local` / `ldap` / `oauth2`；
   - 失败：记录入口 `password_form` / `oauth2`（失败时无法可靠判定账号来源）；
   - 注册：`register`。
   - 需要由 `AuthService.Login` 返回实际方法，web 与 lite 两处共用（[handler.go](../../../server/internal/auth/handler.go)、[lite/auth_handler.go](../../../server/internal/lite/auth_handler.go)）。
2. 新增安全事件 `auth.identity_conflict`（[security_event.go](../../../server/internal/models/security_event.go)），记录用户名、provider、外部 ID、被拒绝的认证源；不记录凭据。
3. 冲突事件按用户名聚合、限频，避免目录侧批量同名导致事件洪泛。
4. 对外错误文案统一为通用提示，避免账号枚举与认证源泄露。

## 5. 接口设计

遵循 [API_STYLE_GUIDE.md](../api/API_STYLE_GUIDE.md)：`/api/v1/web/admin` 命名空间、`snake_case` 字段；`:id` 继续表示用户 UUID。

### 5.1 用户列表

`GET /api/v1/web/admin/users`

新增查询参数：

| 参数 | 类型 | 说明 |
|---|---|---|
| `source` | string | `local` / `ldap` / `oauth2`，白名单校验 |
| `created_via` | string | 可选，按创建渠道过滤 |
| `identity_state` | string | `ok` / `orphaned` / `provider_mismatch` / `inconsistent` |

响应 `users[]` 新增字段：

| 字段 | 说明 |
|---|---|
| `auth_source` | 当前认证归属 |
| `created_via` | 创建渠道 |
| `identity_state` | 派生状态 |
| `provider_name` | provider key（本地账号为空） |
| `external_id` | 外部标识（DN / subject，仅管理员可见） |

实现要求：读取一次配置后在查询层拼接条件，避免逐行计算或全表拉取后内存过滤。

### 5.2 绑定外部身份

`POST /api/v1/web/admin/users/:id/auth-bindings`

```json
{
  "auth_type": "ldap",
  "external_id": "uid=zhangsan,ou=Users,dc=example,dc=com",
  "external_name": "张三"
}
```

规则：

- 仅管理员；provider 由当前启用配置决定，**不接受客户端自定义 provider**。
- 认证源必须已启用且配置完整。
- 同一外部身份已绑定其他用户 → `409`。
- 目标用户已绑定其他来源 → `409`，要求先转本地。
- 事务内：写绑定、`auth_source=auth_type`、清空 `password_hash`。
- 高风险操作，需二次确认并写操作日志。

### 5.3 转为本地账号

`POST /api/v1/web/admin/users/:id/convert-local`

```json
{ "new_password": "至少8位" }
```

- 事务内：写密码、`auth_source=local`、删除全部绑定。
- 密码长度 8~128，与现有管理员重置规则一致。
- 写操作日志，记录原来源与 provider。

### 5.4 重置密码

`PUT /api/v1/web/admin/users/:id/reset-password`

- `auth_source != local` 时返回 `400`：`请先将该用户转为本地账号`。

### 5.5 配置校验

配置保存与启动时都校验（[appconfig/api/handler.go](../../../server/internal/appconfig/api/handler.go)）：

- LDAP 与 OAuth2 同时 `enabled=true` → 拒绝，提示“同一时间只能启用一种第三方认证系统”。
- OAuth2 启用但 `provider_id` 为空 → 拒绝。
- 启动时发现上述问题 → 拒绝启动并给出明确配置错误，避免认证行为不确定。

## 7. 迁移方案

### 7.1 前置只读校验

实施前在线上库执行（只读，不改数据）：

```sql
-- 1. 确认没有 oauth2 关联（预期 0）
SELECT auth_type, COUNT(*) FROM auth_records GROUP BY auth_type;

-- 2. 确认没有重复绑定（预期无结果）
SELECT auth_type, provider_name, external_id, COUNT(*) AS c, COUNT(DISTINCT user_id) AS u
FROM auth_records GROUP BY auth_type, provider_name, external_id HAVING c > 1;

-- 3. 空密码但无 LDAP 关联的用户（回填规则 2 的命中量）
SELECT COUNT(*) FROM users u
LEFT JOIN auth_records r ON r.user_id = u.id AND r.auth_type = 'ldap'
WHERE u.password_hash = '' AND r.id IS NULL;

-- 4. 异常：空密码的管理员（预期 0）
SELECT COUNT(*) FROM users WHERE password_hash = '' AND role = 'admin';

-- 5. 同一用户名大小写变体（预期无结果）
SELECT LOWER(username), COUNT(*) FROM users GROUP BY LOWER(username) HAVING COUNT(*) > 1;
```

若第 1 条出现 `oauth2`、第 4 条大于 0、或第 5 条有结果，先人工处理再进入迁移。

### 7.2 迁移顺序

必须严格按以下顺序，否则会因列不存在或索引冲突导致启动失败：

1. `AutoMigrate` 添加 `users.auth_source`、`users.created_via`（使用默认值）。
2. 归一化 `auth_records.provider_name`：`auth_type='ldap'` 的记录改为 `"ldap"`。
3. 回填 `users.auth_source`：
   - 有 ldap 绑定 → `ldap`；
   - 无绑定且 `password_hash=''` → `ldap`（防御历史记录写入失败）；
   - 其余 → `local`。
4. 回填 `users.created_via='legacy'`。
5. `auth_records` 去重：同一外部身份且同一用户的多条记录保留 `id` 最小的一条；不同用户的冲突不删除，输出报告并中止建索引。
6. 无未决冲突时，通过 Migrator 手动创建唯一索引。
7. 执行一次一致性审计，输出违规账号清单。

**不要**把唯一索引写在 GORM tag 中：`AutoMigrate` 会在去重之前尝试建索引，历史重复数据会直接导致启动失败，也无法实现“有冲突则跳过”的策略。

### 7.3 回填后的预期结果

- 所有 LDAP JIT 用户：`auth_source=ldap`，有 ldap 绑定（或空密码被防御性回填）。
- 所有本地注册/管理员创建用户：`auth_source=local`，无绑定，密码非空。
- `created_via` 全部为 `legacy`；新数据开始记录真实渠道。
- 由于线上无 OAuth2 与同名冲突，不产生“双重身份待复核”账号。

### 7.4 升级注意事项

- 升级后 LDAP 用户仅通过 LDAP 登录；本地用户不再访问目录。
- 升级前确认至少一个 `auth_source=local` 管理员可登录，并妥善保管密码。
- 若历史上存在“LDAP 建号但绑定写入失败”的账号（预检第 3 条命中），首次登录会自动补齐绑定。
- 启用 OAuth2 前必须完成本方案 P2/P3，并配置稳定的 `provider_id`。

- 登录日志：成功记录真实来源，失败记录入口。

## 10. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| 严格路由后 LDAP 故障时外部用户无法登录 | 可用性下降 | 本地管理员 break-glass；发布说明明确 |
| 回填规则误判（空密码账号） | 路由错误 | P0 预检 + 回填后一致性审计 |
| 唯一索引因历史重复创建失败 | 启动失败 | 先检测去重，未决冲突时跳过建索引并告警 |
| 管理员误操作绑定/转本地 | 账号归属变化 | 二次确认 + 操作日志 |
| provider 变更未同步 | 账号显示正常但无法登录 | `provider_mismatch` 状态 + 登录拒绝 |

回滚策略：字段与索引均为增量，代码回滚后旧逻辑仍可运行；`auth_source` 保留不影响旧版本。

## 11. 验收标准

1. 本地账号登录不产生任何 LDAP 请求。
2. LDAP/OAuth2 账号无法通过本地密码登录，本地账号无法通过外部认证登录。
3. 同名冲突被拒绝并产生安全事件，管理员可绑定或转本地。
4. 用户页可按认证来源、创建渠道、身份状态过滤。
5. 停用认证源后账号进入待处理状态；转本地后可登录；重新启用后绑定恢复。
6. `login_logs.method` 能区分成功来源与失败入口。
7. 后端拒绝同时启用 LDAP 与 OAuth2；OAuth2 启用时 `provider_id` 必填。
8. 回填后无 `inconsistent` 账号（或已全部人工处理）。
9. `go test ./...` 与 `yarn build` 通过。

- 每个任务只跑目标包的测试，不跑全量测试，避免并行期间互相干扰。
- 所有新增注释、日志使用中文；接口字段使用 `snake_case`。
