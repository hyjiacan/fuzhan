# FTP 功能审查报告

- 审查日期：2026-09-12
- 审查范围：FTP/FTPS 服务端（`server/internal/ftp/handler.go`、`server/internal/access/ftp/virtual_fs.go`）、服务集成（`server/router.go`、`server/server.go`、`server/main.go`）、配置（`internal/appconfig`、UI 设置页）、FTP/FTPS URL 下载客户端（`server/internal/file/legacy.go`、`url_download.go`）、测试（`server/integration/ftp_handler_test.go`、`ftp_e2e_test.go`）
- 方法：源码静态审查 + 关键疑点本机实测（Go 代码验证）

---

## 一、总体结论

FTP 功能整体结构清晰：基于 `fclairamb/ftpserverlib v0.32.0` + `afero` 虚拟文件系统，匿名/认证双通道，虚拟目录 `public/` + `private/`，路径解析有反斜杠拦截、`..` 词法清洗等防护，登录有失败限速，URL 下载（FTP 客户端侧）的 SSRF 防护已在上一轮安全审查后补齐（`dialFTP` 已带 `Control` 回调复检）。

但存在 **3 个高危问题**（权限模型未落地、FTPS 端口配置失效、大小/配额限制可绕过）和若干中低危问题，主要集中在：FTP 走的是**独立于 Web 上传/权限体系之外的旁路**，绕过全局开关、配额、权限规则与哈希链路；操作记录路径构造错误。

## 二、高危问题

### H1｜public 命名空间权限模型未落地（任意改/删/移）

**位置**：`server/internal/access/ftp/virtual_fs.go`：`Create`(192-216)、`OpenFile`(242-264)、`Remove`(266-280)、`RemoveAll`(282-296)、`Rename`(298-308)

项目既定规则（见索引/上传约定）：公开文件的覆盖上传、重命名、移动、删除——管理员放行；普通用户仅当请求 IP 与索引 `uploaderIp` 一致时放行，否则 403。`FTP_WEBDAV_GUIDE.md` 亦声明 public 目录"可创建新文件，不可修改或删除已有文件"。

实际实现：

| 操作 | 匿名 | 认证用户 | 期望 |
|---|---|---|---|
| STOR 新建 | 允许（仅扩展名校验） | 允许 | 允许 |
| STOR 覆盖已有文件 | **允许**（`O_TRUNC` 写入） | **允许** | 仅上传者/管理员 |
| DELE / RMD | 拦截 | **任意用户可删** | 仅上传者/管理员 |
| RNFR/RNTO 重命名 | **允许** | **任意用户可重命名** | 仅上传者/管理员 |

- `Remove`/`RemoveAll` 只拦截匿名（`userUUID == ""`），任何已登录用户可删除 public 下任意文件，无 `uploaderIp`/角色校验。
- `Rename` 完全无权限与记录；且**无跨命名空间校验**——`RNFR public/files/a.txt` + `RNTO private/b.txt` 可将公共文件移入个人私有目录（窃取），反向可把私有文件移入 public（泄露）。
- 匿名用户可用 `STOR` 覆盖任意已有公共文件、重命名任意文件（仅删除被禁），与"只读/只新建"文档描述矛盾。
- FTP 不校验 `GlobalConfig.Upload.Enabled`（公共目录上传总开关，Web 端在 `file/upload.go` 已实现 403 拦截）——`upload.enabled: false` 对 FTP 无效。

**影响**：任何能连上 FTP 的匿名用户/注册用户可篡改、删除、搬移共享目录中的任意文件，绕过 Web 端全部权限体系。

**建议**：
1. 引入与 Web 端一致的授权判定：写/覆盖/删除/重命名 public 文件时，管理员放行；普通用户校验 `uploaderIp` 一致；匿名一律只允许在目录内**新建**（禁止覆盖、重命名、删除）。
2. `Rename` 校验目标与源同属 public 且同根；禁止 public↔private 跨命名空间。
3. 上传入口校验 `Upload.Enabled`，关闭时返回 `os.ErrPermission`。

### H2｜FTPS 端口配置被忽略，且未强制 TLS

**位置**：`server/internal/ftp/handler.go`：`Start`(241-244)、`GetSettings`(74-83)

- `Start()` 只取 `ftpCfg.Port`（默认 21），**`ftpsCfg.Port`（默认 990）完全不生效**。UI（`SettingsService.vue`）与配置文档均允许单独配置 FTPS 端口 990，文档/FileZilla 指引连接 990，实际服务仍监听在 FTP 端口（21）。
- `GetSettings()` 未设置 `TLSRequired`（ftpserverlib 支持 `ImplicitEncryption` 隐式 TLS），因此即使 FTPS 启用，同端口仍接受**明文 FTP**（仅提供 AUTH TLS 显式加密），与"FTPS 安全访问"预期不符。
- `IsPortInUse` 只检查 FTP 端口；`handler.go` 中 `tlsCfg` 仅当 FTPS 启用时加载，普通 FTP 启用时 `GetTLSConfig` 返回 nil 属预期。

**影响**：配置与行为不一致；管理员以为开启 FTPS 即加密，实际明文口令仍可被抓包；按 990 连接直接失败。

**建议**：
1. FTPS 启用时监听 `ftpsCfg.Port`（默认 990）且设置 `TLSRequired: ftpserverlib.ImplicitEncryption`（隐式 TLS）。
2. 明确语义：FTP 与 FTPS 互斥或独立监听；至少保证文档/UI/实现三者一致。

### H3｜文件大小限制可绕过（REST 续传），配额完全缺失

**位置**：`server/internal/access/ftp/virtual_fs.go`：`sizeLimitedFile`(571-605)

- `sizeLimitedFile` 只跟踪 `Write/WriteAt/WriteString` 累计的 `written`，**不跟踪 `Seek`**。ftpserverlib v0.32.0 支持 REST 命令（对 STOR 会 `Seek` 到续传偏移）。
- 攻击方式：`REST <大偏移>` + `STOR` + 写入 1 字节 → `written=0`，偏移校验只看 `written+len`，绕过 `maxFileSize`（默认 16G），生成稀疏大文件，配合 FTP 不检查任何配额（根目录配额/私有全局/每用户配额）可快速写满磁盘。
- 私有路径上传也无扩展名校验与配额检查（Web 私有上传有 `CheckDiskSpace` + 配额校验）。

**影响**：磁盘耗尽型 DoS；与 Web 上传的配额/大小限制体系完全脱节。

**建议**：
1. `sizeLimitedFile` 重写为按底层文件实际大小/偏移判定：`Seek` 后记录偏移，`Write` 校验 `offset+len <= maxSize`。
2. 在 `Create/OpenFile` 前调用 `services.CheckDiskSpace` 与配额检查（对齐 Web 上传）。

## 三、中危问题

### M1｜FTP 操作记录路径构造错误（FullPath 双重前缀）

**位置**：`server/router.go` 记录回调(134-155) + `virtual_fs.go` `recordFn` 调用点

- FTP 回调传入的 `filePath` 是**虚拟路径**（如 `public/files/a.txt`），`ftpRootName` 返回 `files`。
- `router.go` 拼 `FullPath: "/" + rootName + filePath` → `/files/public/files/a.txt`；`FilePath` 直接存虚拟路径（含 `public/` 前缀）。
- 对照 WebDAV（`internal/access/webdav/recording.go`）：`FilePath` 应为不含 rootName 的相对路径 `/a.txt`，`FullPath` 应为 `/files/a.txt`。
- 与索引表约定（`file_path` 为不含 rootName 的相对路径）不一致 → 最近上传/操作记录页出现无效路径、无法关联索引，点击导航 404。

**建议**：在回调或 FTP 侧将虚拟路径转换为 `rootName` + 相对子路径后按 WebDAV 同款规则构造。

### M2｜操作记录缺失与失真

**位置**：`virtual_fs.go`：`Open`(234-240) 无记录、`Rename`(298-308) 无记录、`Create`(192-216) 传输前落库

- **下载无记录**：`RETR` 走 `Open`，不触发 `recordFn`；文档（`FTP_WEBDAV_GUIDE.md`）声称"上传、下载、创建目录操作会自动记录"且 WebDAV 有下载记录——FTP 缺失。
- **重命名/移动无记录**：`Rename` 不记录（WebDAV 同样不记录 rename，但至少应保持一致并考虑补记）。
- **上传记录失真**：`Create` 时（传输完成前）即落库，`FileSize` 恒为 0；传输中途失败会留下"上传成功"脏记录。

**建议**：上传记录改为传输完成（Close/最终状态）后写入并带真实大小；补充下载/重命名记录（如需要）。

### M3｜FTP 上传未接入索引/哈希链路

**位置**：`internal/index/syncer.go`(97-133)、`internal/index/hashworker.go`

- FTP 上传的公开文件由文件监听器（watcher）增量同步进索引，但 `syncer` 写入的 `FileRecordPublic` **不置 `hash_status=pending`** → 哈希计算要等每日全量扫描（不满足"所有上传路径写入索引后立即触发哈希"的约定）。
- FTP 写入的文件**无 `uploader_ip`** → 按既定权限规则，该文件任何普通用户（含上传者）都无法通过 Web 管理，只能管理员处理。
- FTP **私有**上传完全不写 `file_records_private`（私有目录的文件列表查询自数据库）→ Web 私有页看不到 FTP 上传的文件（仅能看到子目录）。
- FTP 上传也不参与"最近同步标记"，与 Web 上传的防重复处理机制不一致（此处表现为 watcher 正常接手，属可用但链路不一致）。

**建议**：FTP 上传收尾时统一走索引写入（公开写 `file_records_public` 并置 `hash_status=pending`、记录 `uploader_ip`；私有写 `file_records_private`），或至少在 FTP 路径复用统一收尾策略。

## 五、已核实无问题 / 已验证排除

- **路径越界防护**：`cleanFtpPath` 词法清洗 + 反斜杠拦截 + `..` 前缀拦截 + 绝对路径拦截，`..` 中段会被 `path.Clean` 折叠，drive-letter 拼接不构成逃逸。**已实测排除** Windows `.. `（尾随空格）归一化遍历：Go `os` 调用对 `.. ` 组件不做归一化，读取失败（`system cannot find the path specified`）。
- **私有存储布局**：FTP 使用 `{private}/users/{uid}`，与 `file/storage.go` 的 `GetPrivateUserPath` 一致 ✓。
- **URL 下载 FTP 客户端**（`legacy.go`）：`dialFTP` 已带 `Control` 回调复检解析 IP（含 DNS 重绑定防护），`parseFTPURL` 处理 ftp/ftps，TLS 校验默认开启——上一轮审查的 SSRF 问题已修复 ✓。
- **登录限速**：每 IP 5 次失败/5 分钟窗口 + 失败延时，匿名免密登录属预期行为（与文档一致，除 L6 用户名冲突外）。
- **扩展名校验**：public 上传校验 `allowed_extensions`（空 = 不限）✓。
- **测试**：`ftp_e2e_test.go` 覆盖连接/目录/上传/下载/往返/二进制/被动模式/系统信息；`ftp_handler_test.go` 覆盖基础命令；权限模型、REST 绕过、路径穿越、配额超限等负面用例已随修复补齐（见第七章「新增回归测试」）。
