# 文件上传模块

## 模块概述

文件上传模块提供完整的文件上传解决方案，支持本地文件上传、URL远程下载、分片上传断点续传等功能。采用xxh3校验确保数据完整性，支持进度追踪和上传恢复。

---

## 功能列表

### 1. 单文件上传

**功能描述：**
上传本地文件到服务器指定目录。

**接口：**
- **路径：** `POST /api/v1/upload` (需JWT)
- **认证要求：** 需要
- **请求格式：** `multipart/form-data`

**请求参数：**
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| file | File | 是 | 要上传的文件 |
| dir | string | 是 | 上传目录（rootName/subPath格式） |

**响应数据（成功）：**
```json
{
  "success": true,
  "data": {
    "fileName": "document.pdf"
  }
}
```

**验证规则：**
1. 文件类型必须在允许的扩展名列表中
2. 文件大小不能超过配置的最大限制
3. 目标目录必须存在
4. 必须有足够的配额空间

---

### 2. 分片上传（基于会话）

**功能概述：**
分片上传将大文件分割为多个小块上传，支持断点续传、网络恢复和并发上传。采用基于会话的管理模式。

**技术特点：**
- 基于会话的上传管理
- 自定义分片大小（默认5MB）
- xxh3校验确保数据完整性
- 支持断点续传
- 会话过期自动清理

#### 2.1 创建上传会话

**接口：**
- **路径：** `POST /api/v1/uploads/session`
- **认证要求：** 无需认证
- **请求格式：** JSON

**请求参数：**
```json
{
  "filename": "大型文件.zip",
  "fileSize": 104857600,
  "dir": "subdir",
  "rootName": "share1",
  "targetType": "regular"
}
```

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| filename | string | 是 | 文件名 |
| fileSize | int64 | 是 | 文件大小（字节） |
| dir | string | 是 | 上传目录 |
| rootName | string | 是 | 根目录名 |
| targetType | string | 否 | 目标类型 (regular/temp/private) |

**响应数据：**
```json
{
  "success": true,
  "data": {
    "sessionId": "uuid-字符串",
    "chunkSize": 5242880,
    "totalChunks": 20,
    "uploadedChunks": []
  }
}
```

#### 2.2 获取会话状态

**接口：**
- **路径：** `GET /api/v1/uploads/session/:id`
- **认证要求：** 无需认证

**响应数据（部分上传后）：**
```json
{
  "success": true,
  "data": {
    "sessionId": "uuid-字符串",
    "fileName": "大型文件.zip",
    "fileSize": 104857600,
    "chunkSize": 5242880,
    "totalChunks": 20,
    "uploadedChunks": [0, 1, 2, 3],
    "status": "uploading",
    "expiredAt": "2026-01-29T10:00:00Z"
  }
}
```

#### 2.3 续传会话

**接口：**
- **路径：** `POST /api/v1/uploads/session/:id/resume`
- **认证要求：** 无需认证

**响应数据：**
```json
{
  "success": true,
  "data": {
    "sessionId": "uuid-字符串",
    "uploadedChunks": [0, 1, 2, 3],
    "remainingChunks": [4, 5, 6, ...],
    "canResume": true
  }
}
```

#### 2.4 上传单个分片

**接口：**
- **路径：** `POST /api/v1/uploads/chunk`
- **认证要求：** 无需认证
- **请求格式：** `multipart/form-data`

**请求参数：**
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| sessionId | string | 是 | 会话ID |
| chunkIndex | int | 是 | 分片索引（从0开始） |
| file | File | 是 | 分片数据 |
| checksum | string | 否 | xxh3校验值 |

**请求示例：**
```
POST /api/v1/uploads/chunk
Content-Type: multipart/form-data

------WebKitFormBoundary
Content-Disposition: form-data; name="sessionId"

uuid-字符串
------WebKitFormBoundary
Content-Disposition: form-data; name="chunkIndex"

0
------WebKitFormBoundary
Content-Disposition: form-data; name="file"; filename="chunk"
Content-Type: application/octet-stream

[分片数据]
------WebKitFormBoundary--
```

**响应数据（成功）：**
```json
{
  "success": true,
  "data": {
    "uploadedChunks": [0, 1],
    "remaining": 18
  }
}
```

**xxh3校验：**
- 客户端计算分片的xxh3值
- 发送到服务端验证
- 校验失败返回400错误

#### 2.5 取消会话

**接口：**
- **路径：** `DELETE /api/v1/uploads/session/:id`
- **认证要求：** 无需认证

**响应数据：**
```json
{
  "success": true,
  "message": "会话已取消"
}
```

#### 2.6 完成分片上传

**接口：**
- **路径：** `POST /api/v1/uploads/finalize`
- **认证要求：** 无需认证
- **请求格式：** JSON

**请求参数：**
```json
{
  "sessionId": "uuid-字符串"
}
```

**响应数据（成功）：**
```json
{
  "success": true,
  "data": {
    "filePath": "share1/subdir/大型文件.zip",
    "fileSize": 104857600
  }
}
```

**完成流程：**
1. 验证所有分片已上传
2. 合并分片文件
3. 清理分片临时文件
4. 记录上传信息

## 分片上传详解

### 工作原理

```
客户端                              服务端
  |                                   |
  |-- POST /uploads/session --------->|
  |<-- sessionId, chunkSize ----------|
  |  创建会话，返回分片参数            |
  |                                   |
  |-- POST /uploads/chunk (分片0) ---->|
  |<-- uploadedChunks: [0] ------------|
  |                                   |
  |-- POST /uploads/chunk (分片2) ---->|
  |<-- uploadedChunks: [0,2] ---------|
  |  ... (可并发)                      |
  |                                   |
  |-- POST /uploads/finalize -------->|
  |<-- filePath, fileSize -------------|
  |  合并分片，清理临时文件            |
```

### 并发上传

支持多个分片并发上传以提高速度：
- 建议并发数: 2-3
- 服务端按 sessionId + chunkIndex 原子性记录

### 会话恢复

会话保存以下状态：
- 已上传的分片列表
- 文件名和大小
- 目标路径
- 过期时间

**前端持久化策略：**
- 每个上传会话在 localStorage 中独立存储（key 为 `fuzhan_upload_session_{uploadId}`），互不覆盖
- 支持多页面同时上传互不干扰；页面加载时自动恢复所有未完成会话（需重新选择本地文件续传）
- 浏览器重启后仍可自动恢复（localStorage 持久化），服务端会话过期前有效

## xxh3校验

### 实现原理

xxh3 是一种高性能的非加密哈希算法，比CRC32更快。

**Go实现：**
```go
import "github.com/zeebo/xxh3"

// 计算 xxh3 哈希
hash := xxh3.Hash(data)
return fmt.Sprintf("%x", hash) // 十六进制字符串
```

**JavaScript实现：**
```javascript
import { xxhash3 } from 'hash-wasm'

// 计算 xxh3 哈希
const checksum = await xxhash3(buffer)
return checksum // BigInt 转换为字符串
```

## 错误处理

| 错误代码 | 错误信息 | 原因 |
|---------|---------|------|
| 400 | 解析表单错误 | 表单数据格式错误 |
| 400 | 未选择要上传的文件 | file字段为空 |
| 400 | 不支持的文件类型 | 扩展名不在允许列表中 |
| 400 | 文件大小超过限制 | 超过配置的最大限制 |
| 400 | 根目录不存在 | 指定的rootName未配置 |
| 400 | 路径越权 | 试图访问根目录外的路径 |
| 400 | 配额检查失败 | 目录空间不足 |
| 400 | 分片索引超出范围 | chunkIndex不在有效范围内 |
| 400 | xxh3校验失败 | 分片数据校验不匹配 |
| 400 | sessionId不能为空 | 会话ID缺失 |
| 404 | 上传会话不存在 | 会话已过期或不存在 |
| 409 | 文件已经存在 | 文件已存在 |
| 500 | 创建文件失败 | 磁盘权限或空间问题 |
| 500 | 保存文件失败 | 磁盘I/O错误 |

## 前端集成

### 分片上传示例

```javascript
class ChunkedUploader {
  constructor(file, dir, rootName, options = {}) {
    this.file = file;
    this.dir = dir;
    this.rootName = rootName;
    this.chunkSize = options.chunkSize || 5 * 1024 * 1024; // 5MB
    this.concurrency = options.concurrency || 2;
  }

  async upload() {
    // 1. 创建会话
    const sessionRes = await this.createSession();
    if (sessionRes.data.completed) {
      console.log('文件已存在');
      return;
    }

    const { sessionId, chunkSize, totalChunks } = sessionRes.data;
    this.sessionId = sessionId;
    this.chunkSize = chunkSize;

    // 2. 获取已上传的分片
    const statusRes = await this.getSessionStatus();
    const uploadedChunks = new Set(statusRes.data.uploadedChunks || []);

    // 3. 上传未完成的分片
    const pendingChunks = [];
    for (let i = 0; i < totalChunks; i++) {
      if (!uploadedChunks.has(i)) {
        pendingChunks.push(i);
      }
    }

    // 4. 并发上传
    await this.uploadChunks(pendingChunks);

    // 5. 完成上传
    await this.finalize();
  }

  async createSession() {
    const res = await fetch('/api/v1/uploads/session', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        filename: this.file.name,
        fileSize: this.file.size,
        dir: this.dir,
        rootName: this.rootName
      })
    });
    return res.json();
  }

  async getSessionStatus() {
    const res = await fetch(`/api/v1/uploads/session/${this.sessionId}`);
    return res.json();
  }

  async uploadChunks(chunkIndices) {
    const uploadChunk = async (index) => {
      const start = index * this.chunkSize;
      const end = Math.min(start + this.chunkSize, this.file.size);
      const chunk = this.file.slice(start, end);

      const formData = new FormData();
      formData.append('sessionId', this.sessionId);
      formData.append('chunkIndex', index);
      formData.append('file', chunk);

      const res = await fetch('/api/v1/uploads/chunk', {
        method: 'POST',
        body: formData
      });
      return res.json();
    };

    // 并发控制
    for (let i = 0; i < chunkIndices.length; i += this.concurrency) {
      const batch = chunkIndices.slice(i, i + this.concurrency);
      await Promise.all(batch.map(uploadChunk));
    }
  }

  async finalize() {
    const res = await fetch('/api/v1/uploads/finalize', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ sessionId: this.sessionId })
    });
    return res.json();
  }
}

// 使用
const fileInput = document.getElementById('file');
fileInput.onchange = async () => {
  const uploader = new ChunkedUploader(
    fileInput.files[0],
    'uploads',
    'share1'
  );
  await uploader.upload();
};
```

## 安全考虑

### 已实现措施

1. **文件类型验证**
   - 扩展名白名单
   - MIME类型检查

2. **大小限制**
   - 最大文件大小配置
   - 目录配额检查

3. **路径安全**
   - 路径越权检查
   - 目录遍历防护

4. **数据完整性**
   - xxh3校验
   - 分片索引验证

5. **会话管理**
   - 会话过期机制
   - 自动清理

6. **覆盖权限（公共文件上传者IP归属）**
   - 目标文件已存在时，默认仅在前端显式传入覆盖标记（`allowOverwrite=true`）或满足以下条件时才允许覆盖：
     - 请求者为管理员；或
     - 当前请求IP与该公共文件索引记录中的 `uploaderIp` 一致（上传者本人）。
   - 分片上传与 URL 下载均在落盘后把上传者来源IP写入索引记录的 `uploader_ip` 字段，用于后续"IP一致允许覆盖/重命名/移动/删除"的归属校验。覆盖上传会重新绑定归属。

### 建议改进

1. **病毒扫描** - 上传后扫描文件
2. **速率限制** - 单用户上传频率限制
3. **加密传输** - 强制HTTPS
