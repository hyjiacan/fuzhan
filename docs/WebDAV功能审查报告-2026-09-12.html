WebDAV 功能审查报告 · 2026-09-12

审查范围：WebDAV 服务端（server/internal/access/webdav/）、路由装配（server/router.go）、配置（internal/appconfig）、E2E（server/integration/webdav_e2e_test.go）、文档（docs/FTP_WEBDAV_GUIDE.md）
方法：源码静态审查 + 与已修复的 FTP 功能同口径对照（两次功能共用统一端点/虚拟文件系统/文档声明）
高
总体：WebDAV 存在 3 个高危缺口。核心问题在于 WebDAV 是一条未接入 Web 上传/权限/索引/审计体系的旁路：上传不写索引表、不触发哈希、不计入操作记录、不校验全局上传开关与配额，且配置里的 Port 是死配置。路径越界、公开只读语义、私有目录隔离三处安全边界本身实现良好，与 FTP 修复后水准一致。

一、高危问题

H1操作录制装饰器是死代码 —— WebDAV 全部操作未落审计记录

位置：server/router.go:520-541 · internal/access/webdav/recording.go

  • 路由装配直接用 NewUnifiedFileSystem(publicFS, privateFS) 构造 webdav.NewHandler，全程没有包裹 RecordingFileSystem。全仓库搜索显示 RecordingFileSystem 仅在 recording_test.go 中被引用，生产代码零调用。
  • docs/FTP_WEBDAV_GUIDE.md 明确声明“上传、下载、创建目录操作会自动记录到 operation_records 表中”，但实际 WebDAV 的 PUT / MKCOL / GET 均不产生任何操作记录，审计链路完全缺失。
  • 即便有人误挂该装饰器，其 splitPath(name) 对统一路径拆分也会把 rootName 取成 public/private 而非真实共享根名（与 FTP 已修复的 M1 同源，WebDAV 侧从未接入）。

H2上传未接入索引表 / 哈希链路 / uploader_ip（公开与私有均缺失）

位置：internal/access/webdav/public.go:60-93 · internal/access/webdav/private.go:80-89

  • 两套文件系统对文件写操作直接走 os.OpenFile 落盘，不写 file_records_public / file_records_private、不写 uploader_ip、不触发 TriggerHash。
  • 公开上传：仅会靠文件监听器（watcher）增量同步进索引，但 watcher 写入不置 hash_status=pending → 哈希要等每日全量扫描才计算（违反“所有上传路径写入索引后立即触发哈希”）；且无 uploader_ip → 按既定权限规则，该文件任何普通用户（含上传者本人）都无法在 Web 端管理，只能管理员处理。同时不进入“最近上传”“最新版本”“重复文件”检索。
  • 私有上传：不写 file_records_private → Web 私有文件页查询自数据库，看不到 WebDAV 上传的文件（只会出现子目录），也无法通过分享码分享。

H3全局上传开关 Upload.Enabled 与扩展名校验被绕过

位置：internal/access/webdav/public.go:39-50,60-93 · 对照 internal/file/upload.go:109 / internal/access/ftp/virtual_fs.go:264

  • 匿名用户即可用 PUT 新建公开文件、MKCOL 建目录；public.go 整体未引用 GlobalConfig.Upload.Enabled（FTP 修复后已在 Create/OpenFile 校验该开关，WebDAV 全无）。upload.enabled: false 时 Web 端 403，但 WebDAV 照常可写。
  • 同样未校验 Storage.AllowedExtensions 扩展名白名单（FTP public 上传已校验），管理员若限制了可上传类型，WebDAV 可绕过上传任意后缀。

二、中危问题

M1无磁盘空间 / 配额校验（磁盘耗尽 DoS）

位置：public.go / private.go 全部写入口

  • 公开与私有上传入口均不调用 services.CheckDiskSpace 与用户配额检查（FTP 修复后已前置 CheckDiskSpace 并做真实大小配额校验）。
  • 匿名可连续 PUT（每个受 MaxFileSize 上限），配合公开目录可无限堆积，达到磁盘耗尽型 DoS；私有上传也绕过分区剩余空间与每用户配额。

M2配置项 server.webdav.port 为死配置

位置：internal/appconfig/config.go:80-84 · internal/config/handler.go:41-42,306-312 · server/router.go:520-541

  • config / DTO / 配置 API 均读写并向前端暴露 Server.WebDAV.Port，但运行期 WebDAV 直接挂在主 HTTP 服务的 /api/v1/webdav 上，没有任何独立监听该端口（server.go/main.go 均无引用）。
  • 管理员在设置页配置端口后不会产生任何行为变化，文档/UI/实现三者不一致（与 FTP 已修复的 H2 同理）。

M3Basic 认证无失败限速

位置：internal/access/webdav/auth.go:115-161

  • WebDAV Basic Auth 无每 IP 失败计数/限速（FTP 有 failCounts，Web 登录亦有速率限制），仅依赖 bcrypt 计算成本被动缓释；对私有的暴力猜测在低成本并行下可被放大。

三、低危问题

编号问题位置与影响
L1GET 不受下载限流WebDAV GET 未接入 accessguard（Web /download 有 1 分钟 120 次限流）。公开文件可被匿名反复拉取造成带宽 DoS。
L2E2E 断言过宽且无负面用例webdav_e2e_test.go 多个断言接受 2xx/403/405/404 多种状态码；私有 PROPFIND 注释自认“may fail”放行。未覆盖操作记录、索引/哈希、配额、Upload.Enabled、symlink 逃逸、跨命名空间重命名等负面场景，无法捕获本次三类高危回归。
L3公开新建存在 TOCTOU 竞态public.go:79-84 先 os.Stat 判断不存在再 os.OpenFile(..., O_CREATE|O_TRUNC)，并发下若文件在两者之间被他人创建，可能清空该已有文件。可改用 O_EXCL 原子判定。

四、已验证无问题 / 已核实通过

  • ✓ 公开只读/只新建语义：覆盖已有文件返回 ErrPermission；RemoveAll/Rename 一律拒绝；UnifiedFileSystem.Rename 禁止 public↔private 跨命名空间移动。
  • ✓ 路径越界防护：公开侧 PathValidator.Validate 做词法边界 + EvalSymlinks 符号链接逃逸拦截（根内 symlink 指向根外会被拒绝）；私有侧 PrivateFileSystem.validatePath 解析双方 symlink 后比对真实落点。
  • ✓ 私有目录隔离：按 context 中用户 UUID 定位 {private}/users/{uid}；匿名访问 /private 返回 ErrPermission，不泄露私存存在性（优于 FTP L3 已修前状态）。
  • ✓ PROPFIND 深度限制：depthMiddleware 拒绝 infinity 及非法 Depth，防止递归枚举。
  • ✓ 写请求 body 封顶：bodyLimitMiddleware 用 http.MaxBytesReader 按 Upload.MaxFileSize 限制 PUT/PROPPATCH 请求体（0 = 不限）。
  • ✓ 认证缓存：合并写锁二次校验 TTL，避免 TOCTOU；凭据用 xxh3 摘要作 key，不明文落缓存。

五、修复优先级建议

优先级问题建议落点
P0H3 全局开关 / 扩展名校验统一文件系统写入口（公开 Mkdir / OpenFile-create）前置 Upload.Enabled 与 AllowedExtensions 校验。
P0H2 索引 / 哈希 / uploader_ip 链路公开上传收尾写 file_records_public（hash_status=pending + uploader_ip）+ TriggerHash；私有上传写 file_records_private（32 位分享码）。复用统一收尾策略。
P1H1 操作录制接线在 router.go 用 NewRecordingFileSystem 包裹 unifiedFS，并修正 splitPath 为 rootName + 带前导 / 相对路径。
P1M1 磁盘 / 配额检查公开与私有写入口前置 services.CheckDiskSpace；私有上传做真实大小配额校验。
P2M2 死配置 / M3 认证限速 / L1-L3移除或打通 webdav.port；Basic Auth 按 IP 失败限速；GET 接入下载限流；补负面 E2E；公开新建改 O_EXCL。
