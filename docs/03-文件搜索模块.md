# 文件搜索模块

## 模块概述

文件搜索模块提供跨多根目录的实时文件搜索功能。采用Server-Sent Events（SSE）技术实现流式数据传输，支持按文件名和扩展名搜索，使用并发goroutine提升搜索性能，并支持搜索取消功能。

---

## 功能列表

### 1. 实时文件搜索

**功能描述：**
在所有配置的根目录中搜索匹配的文件和目录，实时返回搜索结果。

**接口：**
- **路径：** `GET /api/v1/search/*query`
- **认证要求：** 需要
- **响应类型：** `text/event-stream`（Server-Sent Events）

**请求参数：**
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| query | string | 是 | 搜索关键词（URL路径的一部分） |

**请求示例：**

**基础搜索：**
```
GET /api/v1/search/report
```
搜索所有包含"report"的文件和目录。

**按扩展名搜索：**
```
GET /api/v1/search/report.pdf
```
搜索文件名包含"report"且扩展名为"pdf"的文件。

**URL编码的搜索：**
```
GET /api/v1/search/%E6%96%87%E6%A1%A3
```
搜索"文档"（中文关键词需URL编码）。

**响应格式：**

每个结果以SSE数据格式发送：
```
data: {"success":true,"message":"","data":[{"name":"report.pdf","type":"file","path":"documents/report.pdf","modifiedTime":"2026-01-28T10:30:00Z","size":1048576}]}

```

**搜索完成消息：**
```
data: {"success":true,"message":"搜索完成，共找到 15 个结果","data":[]}

```

**结果限制提示：**
```
data: {"success":true,"message":"检索结果超过 1000，中止检索","data":[]}

```

## 搜索功能详解

### 搜索模式

#### 1. 文件名搜索

**语法：** 直接输入关键词

**匹配规则：**
- 不区分大小写
- 支持部分匹配（包含关键词即可）
- 同时搜索文件和目录

**示例：**
- `report` → 匹配：`report.pdf`、`annual_report.docx`、`reports/`
- `2024` → 匹配：`2024_summary.xlsx`、`data2024/`

#### 2. 扩展名过滤

**语法：** `关键词.扩展名`

**匹配规则：**
- 文件名包含关键词
- 扩展名完全匹配
- 不搜索目录（只搜索文件）
- 文件类型必须被允许（根据配置）

**示例：**
- `report.pdf` → 匹配：`quarterly_report.pdf`、`report2024.pdf`
- `data.xlsx` → 匹配：`data.xlsx`、`q1_data.xlsx`
- **不匹配：** `report.docx`（扩展名不同）

### 并发搜索

**技术实现：**
- 为每个根目录启动独立的goroutine
- 使用通道（channel）收集搜索结果
- 使用WaitGroup协调所有搜索进程

**优势：**
- 多个目录同时搜索，提升速度
- 结果按找到顺序实时推送
- 搜索过程中断不影响其他目录

**流程图：**
```
客户端
  ↓ [搜索请求]
  ↓/
主处理器
  ↓ →|Goroutine 1|→ 根目录1 → 结果通道
  ↓ →|Goroutine 2|→ 根目录2 → 结果通道
  ↓ →|Goroutine 3|→ 根目录3 → 结果通道
  ↓
结果收集器 → 实时推送结果
    ↓
搜索完成通知
```

### 实时流式传输

**技术特点：**
- 使用Server-Sent Events (SSE)
- 边搜索边返回结果
- 每找到一条立即发送

**响应头：**
```
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
```

**客户端处理示例：**
```javascript
const eventSource = new EventSource('/api/v1/search/report', {
  headers: {
    'Authorization': `Bearer ${token}`
  }
});

eventSource.onmessage = function(event) {
  const data = JSON.parse(event.data);
  if (data.data.length > 0) {
    // 处理搜索结果
    displayResult(data.data[0]);
  }
  if (data.message.includes('搜索完成')) {
    eventSource.close();
    console.log(`共找到 ${data.message.match(/找到 (\d+) 个/)[1]} 个结果`);
  }
};

eventSource.onerror = function(event) {
  eventSource.close();
};
```

### 搜索取消

**触发条件：**

1. **客户端断开连接**
   - 用户关闭浏览器标签
   - 导航到其他页面
   - 手动关闭EventSource

2. **结果数量超限**
   - 找到超过1000条结果
   - 自动停止搜索以保护服务器资源

**实现机制：**
- 使用Context控制goroutine生命周期
- 监听`CloseNotify`信号
- 主动发送取消信号给所有搜索进程

**代码示意：**
```go
// 监听客户端断开
notify := w.(http.CloseNotifier).CloseNotify()
go func() {
    <-notify
    cancel() // 取消搜索
}()

// 每个搜索goroutine检查Context
select {
case <-ctx.Done():
    return ctx.Err() // 提前退出
}
```

## 搜索算法

### 目录遍历

使用`filepath.Walk`递归遍历目录树：

**特性：**
- 深度优先搜索（DFS）
- 自动处理子目录
- 支持取消

**性能考虑：**
- 避免搜索系统目录（通过配置限制）
- 跳过隐藏的临时文件
- 支持部分搜索（上下文取消）

### 字符串匹配

**实现：**
```go
fileNameLower := strings.ToLower(filename)
queryLower := strings.ToLower(query)

// 部分匹配
strings.Contains(fileNameLower, queryLower)
```

**优点：**
- 简单高效
- 支持模糊搜索
- O(n)时间复杂度

### 扩展名处理

**解析逻辑：**
```go
// 提取扩展名
fileExt := strings.ToLower(
    strings.TrimPrefix(filepath.Ext(filename), ".")
)

// 解析查询
parts := strings.SplitN(query, ".", 2)
namePart := parts[0]
extPart := parts[1]
```

**匹配规则：**
- 文件名包含关键词
- 扩展名完全匹配
- 忽略大小写

## 性能特性

### 并发处理

**配置：**
- 每个根目录一个goroutine
- 结果通过通道汇总
- 无需锁（channel自带并发安全）

**基准测试数据（参考）：**
- 10,000个文件搜索：< 1秒
- 100,000个文件搜索：2-5秒
- 结果实时推送，用户体验流畅

### 资源限制

**结果数限制：**
- 最多返回1000条结果
- 超限时自动停止
- 防止内存溢出

**内存使用：**
- 通道缓冲由系统自动优化
- 单次处理一个结果，不累积
- 客户端断开立即释放资源

### 网络优化

**流式传输：**
- 无需等待全部完成
- 逐批发送结果
- 减少延迟感知

**压缩选项（可扩展）：**
- SSE支持压缩
- 可配置启用GZIP压缩

## 前端集成

### 搜索组件示例

```vue
<template>
  <div>
    <el-input
      v-model="searchQuery"
      placeholder="搜索文件..."
      @keyup.enter="startSearch"
      clearable
    >
      <template #prepend>
        <el-icon><Search /></el-icon>
      </template>
    </el-input>

    <el-divider />

    <el-table :data="searchResults" v-loading="searching">
      <el-table-column prop="name" label="文件名" />
      <el-table-column prop="type" label="类型">
        <template #default="{ row }">
          <span>{{ row.type === 'file' ? '文件' : '目录' }}</span>
        </template>
      </el-table-column>
      <el-table-column prop="size" label="大小">
        <template #default="{ row }">
          <span>{{ formatFileSize(row.size) }}</span>
        </template>
      </el-table-column>
      <el-table-column prop="modifiedTime" label="修改时间" />
      <el-table-column label="操作">
        <template #default="{ row }">
          <el-button size="small" @click="downloadFile(row)">下载</el-button>
        </template>
      </el-table-column>
    </el-table>

    <div v-if="searchComplete" class="search-status">
      {{ searchStatus }}
    </div>
  </div>
</template>

<script setup>
import { ref } from 'vue'

const searchQuery = ref('')
const searchResults = ref([])
const searching = ref(false)
const searchComplete = ref(false)
const searchStatus = ref('')

let eventSource = null

const startSearch = async () => {
  if (!searchQuery.value) return

  // 清理之前的搜索
  if (eventSource) eventSource.close()
  searchResults.value = []
  searching.value = true
  searchComplete.value = false

  eventSource = new EventSource(`/api/v1/search/${encodeURIComponent(searchQuery.value)}`, {
    headers: {
      'Authorization': `Bearer ${localStorage.getItem('token')}`
    }
  })

  eventSource.onmessage = (event) => {
    const data = JSON.parse(event.data)
    if (data.data && data.data.length > 0) {
      searchResults.value.push(data.data[0])
    }
    if (data.message.includes('搜索完成')) {
      searching.value = false
      searchComplete.value = true
      searchStatus.value = data.message
      eventSource.close()
    }
  }

  eventSource.onerror = () => {
    searching.value = false
    searchComplete.value = true
    searchStatus.value = '搜索出错或被中断'
    eventSource.close()
  }
}

const formatFileSize = (bytes) => {
  if (bytes < 1024) return bytes + ' B'
  if (bytes < 1024 * 1024) return (bytes / 1024).toFixed(2) + ' KB'
  return (bytes / (1024 * 1024)).toFixed(2) + ' MB'
}
</script>
```

## 嵌入式检索模块（Bluge + gse）

### 背景

现有搜索基于 `filepath.Walk` 实时遍历 + `strings.Contains` 的部分匹配，无法支持**自动补全**与**拼写纠错**这类"输入过程中的联想/纠错"体验，且在大目录下存在整树遍历开销。

新检索模块使用 **Bluge**（嵌入式倒排索引，零外部服务）+ **gse**（中文分词）实现轻量级文件名索引，作为现有搜索的有益补充。

### 代码位置

- **模块包：** `server/internal/search`
- **独立演示入口：** `server/cmd/searchdemo`（`go run ./cmd/searchdemo`）
- **索引存储：** `<work_dir>/data/search_index`

### 核心能力

| 方法 | 说明 |
|------|------|
| `SearchIndex.IndexFile(fileID int64, fileName string)` | 写入/更新单条文件名索引 |
| `SearchIndex.Delete(fileID int64)` | 文件删除/移动后同步删除索引 |
| `SearchIndex.AutoComplete(prefix string, limit int)` | 自动补全，基于前缀查询 |
| `SearchIndex.SpellCheck(word string, limit int)` | 拼写纠错，Fuzzy 查询（fuzziness=2，prefix_length=1） |
| `SearchIndex.CloseWriter()` | 优雅停机，刷盘释放 |

### 分词策略（自定义 Analyzer）

- **中文**：gse 切分成语义单元（如 `年度财务报表` → 年度/财务/报表）
- **英文/数字**：N-gram（min=2, max=4）生成片段，支持只记得部分名称的检索
- **统一小写**：`LowerCaseFilter`，使 `README`/`readme`/`Readme` 等价
- 字段 `file_name` 调用 `StoreValue()`，查询命中直接回读文件名

### HTTP 接口

| 接口 | 认证 | 说明 |
|------|------|------|
| `GET /api/v1/search-suggest?q=<前缀>&limit=<数量>` | 无需 | 自动补全，返回 `data: []string`（匹配的文件名） |
| `GET /api/v1/search-spellcheck?q=<单词>&limit=<数量>` | 无需 | 拼写纠错，返回 `data: []string`（最相似的文件名候选） |

`limit` 默认值：自动补全 10（上限 30）、纠错 5（上限 10）。`q` 需 URL 编码（中文必须编码）。

### 构建与同步

- **全量构建：** 启动时 `RebuildFromDB` 从 `file_records_public`（status=active）分批（每批 500）重建索引，幂等覆盖（按 fileID）。
- **增量同步：** 通过 `FileIndexNotifier` 接口注入到索引同步器 `Syncer`，文件创建/更新/删除/移动后自动增删改 Bluge 索引（按 fileID 定位），保证与 `file_records_*` 索引表一致，避免"搜到已删文件 / 旧文件名"髒数据。
- **优雅停机：** `CloseWriter` 在进程退出时刷盘并关闭索引。

### 调度与任务管理（无定时任务、不入任务管理）

- **无定时重建任务**：检索索引只在服务**启动时**全量重建一次（`RebuildFromDB`，同步执行，阻塞到完成），之后完全依赖文件变更的增量同步（`IndexFile`/`Delete`）。系统**没有**为它配置任何 cron 定时重建任务，也没有管理界面的"重建检索索引"入口。索引文件存放于 `<work_dir>/data/search_index`。
- **不写入任务管理**：任务管理（任务表 `task_records`，管理页"任务管理"）记录的是**索引全量扫描**与**哈希计算**任务（由 `index.Service.SetTaskService` 注入的 `TaskRecorder`，供 `Scanner`、`HashWorker` 使用）。Bluge 的全量构建与增量同步**均未接入 `TaskRecorder`**，因此任务管理页**看不到 Bluge 相关任务**。
- **一致性保障**：检索索引与索引表的一致性依赖"文件变更事件驱动 + 启动时全量重建兜底"，无需额外后台任务。

### 前端集成

搜索框使用 `el-autocomplete` 的 `fetch-suggestions`，并行请求 `search-suggest`（自动补全，直接推荐）与 `search-spellcheck`（纠错候选，标注"纠错"徽标），合并去重后展示；选中推荐项即以该文件名发起搜索。

### 业务效果（已实现）

1. **自动补全**：用户输入关键词时实时给出联想文件名，选中即可查询
2. **拼写纠错**：检测到疑似拼写错误时，下拉候选标注"纠错"，点击直达对应文件
3. **中英文混排**：英文/数字前缀（如 `fir` → Firefox 系列）、中文前缀（如 `海尼` → 海尼曼系列）均支持

### 一致性要求

文件存在创建 / 删除 / 移动 / 重命名，Bluge 索引必须随之**增删改（按 fileID 定位）**，避免"搜到已删文件/旧文件名"的脏数据；该约束与现有 `file_records_*` 索引表一致。

   - 限制单用户搜索频率

4. **编码问题：**
   - 中文关键词需URL编码
   - 特殊字符需转义
