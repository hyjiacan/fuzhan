# 临时文件管理设计文档

## 概述

临时文件管理是轻共享系统的一个重要功能模块，允许用户上传临时文件并生成访问链接进行分享。这些文件具有过期时间，可以在指定时间后自动删除，适合短期文件分享需求。

## 功能特性

### 1. 用户标识管理
- 每个用户拥有唯一的 32 位十六进制用户标识 (UUID)
- 用户标识存储在浏览器本地存储中，用于关联用户上传的文件
- 支持用户标识的恢复和重置功能

### 2. 文件上传
- 支持本地文件上传和 URL 文件下载
- 支持设置文件过期时间（默认 7 天）
- 支持永不过期选项
- 支持大文件分片上传和断点续传

### 3. 文件去重机制
- 使用 SHA256 哈希算法计算文件指纹
- 通过引用计数机制管理相同文件的多个实例
- 节省存储空间，提高上传效率

### 4. 文件分享
- 为每个文件生成 8 位十六进制访问码
- 通过访问码生成下载链接进行文件分享
- 支持文件延期功能

### 5. 存储配额
- 支持全局临时文件存储配额限制
- 支持每用户临时文件存储配额限制
- 实时显示存储使用情况和配额信息

## 系统架构

### 数据存储结构

```
临时文件根目录 (config.Temp.Path)
├── users/                    # 用户目录
│   └── {user_id}/            # 每个用户的目录
│       └── {file_identifier}/ # 文件标识目录
│           ├── data          # 文件数据（引用文件）
│           ├── meta.json     # 文件元数据
│           └── chunks/       # 分片上传临时目录
├── files/                    # 持久文件存储
│   └── {file_hash}/          # 每个唯一文件的目录
│       ├── file.data         # 实际文件数据
│       └── meta.json         # 文件元数据
├── references/               # 文件引用记录
│   └── {file_hash}.json      # 文件引用信息
└── identifiers/              # 用户标识信息
    └── {user_id}.json        # 用户标识元数据
```

### 核心数据结构

#### 1. 临时文件元数据 (TempFileMeta)
```go
type TempFileMeta struct {
    Filename   string    `json:"filename"`   // 文件名
    UploadTime time.Time `json:"uploadTime"` // 上传时间
    FileSize   int64     `json:"fileSize"`   // 文件大小
    Owner      string    `json:"owner"`      // 文件所有者（用户ID）
    Code       string    `json:"code"`       // 访问码
    ExpireTime time.Time `json:"expireTime"` // 过期时间
    FileHash   string    `json:"fileHash"`   // 文件哈希（用于去重）
}
```

#### 2. 文件引用信息 (FileReference)
```go
type FileReference struct {
    FileHash    string    `json:"fileHash"`    // 文件哈希
    FilePath    string    `json:"filePath"`    // 文件路径
    FileSize    int64     `json:"fileSize"`    // 文件大小
    RefCount    int       `json:"refCount"`    // 引用计数
    CreatedTime time.Time `json:"createdTime"` // 创建时间
}
```

#### 3. 用户标识信息 (UserIdentifier)
```go
type UserIdentifier struct {
    ID        string    `json:"id"`        // 用户标识
    IPAddress string    `json:"ipAddress"` // IP地址
    CreatedAt time.Time `json:"createdAt"` // 创建时间
}
```

## 工作流程

### 1. 用户标识生成与验证
1. 用户首次访问时，前端检查本地存储中的用户标识
2. 如果不存在，向服务器请求生成新的用户标识
3. 服务器生成 UUID 并移除连字符，返回 32 位十六进制标识
4. 前端将标识存储在本地存储中

### 2. 临时文件上传流程
1. 用户选择文件并设置过期时间
2. 前端检查文件是否已存在（通过文件名和用户ID生成稳定标识）
3. 如果是分片上传，检查上传状态获取已上传分片信息
4. 上传文件分片并进行 CRC32 校验
5. 所有分片上传完成后，合并分片并计算文件 SHA256 哈希
6. 检查文件是否已存在，如果存在则增加引用计数
7. 如果文件不存在，保存到持久存储目录
8. 创建用户引用记录和文件元数据
9. 生成 8 位访问码并返回给用户

### 3. 文件下载流程
1. 用户通过访问码请求下载文件
2. 系统遍历所有用户目录查找对应访问码
3. 验证文件是否存在且未过期
4. 读取引用文件获取实际文件路径
5. 返回文件内容给用户

### 4. 文件清理流程
1. 系统定期（每小时）执行清理任务
2. 遍历所有用户目录中的文件
3. 检查文件是否已过期
4. 删除过期文件并减少引用计数
5. 如果引用计数为 0，删除实际文件和引用记录

## 安全机制

### 1. 访问控制
- 每个文件只能由其所有者管理
- 通过用户标识验证文件访问权限
- 访问码用于公开分享，无需用户标识即可下载

### 2. 数据保护
- 文件哈希用于确保文件完整性
- 分片上传过程中进行 CRC32 校验
- 敏感信息（如用户标识）通过 HTTP 头传递

### 3. 存储安全
- 文件去重机制防止恶意上传相同文件消耗存储空间
- 配额限制防止存储空间被过度占用
- 定期清理过期文件释放存储空间

## 前端实现

### 1. 用户界面组件
- 上传区域：支持文件选择、过期时间设置
- 用户标识管理：显示和恢复用户标识
- 文件列表：展示用户上传的文件及状态
- 存储信息：显示配额使用情况

### 2. 核心模块
- TempModule：临时文件管理主模块
- MD5Calculator：MD5 计算模块（用于文件去重）
- ChunkUploader：分片上传器（继承自主上传功能）

### 3. 交互流程
1. 用户点击"临时文件"按钮打开管理界面
2. 系统检查用户标识并验证有效性
3. 加载用户文件列表和存储信息
4. 用户可上传文件、下载文件、延期或删除文件
5. 所有操作通过 AJAX 请求与后端交互

## 性能优化

### 1. 文件去重
- 通过 SHA256 哈希避免存储相同文件的多个副本
- 引用计数机制管理文件生命周期

### 2. 分片上传
- 支持大文件断点续传
- 并发上传提高上传速度
- CRC32 校验确保数据完整性

### 3. 存储管理
- 定期清理任务释放存储空间
- 配额限制防止资源滥用
- 引用计数机制自动清理无用文件
