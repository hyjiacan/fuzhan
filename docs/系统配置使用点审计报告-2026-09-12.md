## 一、结论摘要

以「配置能用且按预期生效」为准则，本次核对确认了 **2 个真实使用链缺陷（本次已修复）**、**1 处死配置残留（本次已清理）**、以及若干 **【文档/界面缺口】与【建议】项**。审计过程中对初轮自动化发现的部分问题做了人工复核，发现并剔除了 4 处误报（见「四、复核剔除的误报」），确保本报告结论可溯源、真实。

## 二、已修复的问题

### 2.1 【已修复·高】`upload.url_upload.allowed_ip_ranges` 保存链不完整
- **现象**：该字段在 `config.go`（`URLUploadConfig.AllowedIPRanges`）与 `fuzhan.yaml` 中均有声明，加载解析也能正确读到（`config_load.go` 复用 `URLUploadConfig`），但**保存接口与 DTO 均缺少该字段**，导致管理员通过设置保存时该配置无法写回、实际不生效（等于「配了但存不住」）。
- **证据**：
  - `internal/appconfig/dto.go` `URLUploadDTO` 原只有 `enabled`/`insecureSkipVerify`。
  - `internal/config/handler.go` 保存逻辑原只写 `enabled`/`insecure_skip_verify`，未写 `allowed_ip_ranges`。
  - `ui/src/views/SettingsView.vue` 原 `urlUpload` 只含 `enabled`/`insecureSkipVerify`。
- **处理**：已在 DTO（结构体、`ToDTO`、`ApplyToConfig`）、保存 handler（赋值 + `updates.Add("upload.url_upload.allowed_ip_ranges", …)`）、运行时 GET 配置响应、前端 `settings.upload.urlUpload` 默认与加载映射中补齐 `allowedIPRanges`，构成完整保存链路。

### 2.2 【已清理·高】`server.webdav.port` 死配置残留
- **现象**：`server/fuzhan.yaml` 中残留 `webdav: { enabled: false, port: 0 }`，而 `WebDAVConfig` 结构体仅有 `Enabled`，WebDAV 也已是统一端点 `/api/v1/webdav`，`port` 属早期版本的死配置（`fuzhan.sample.yaml` 早已移除）。
- **处理**：已从 `fuzhan.yaml` 删除 `server.webdav.port`，仅保留 `enabled`。

## 三、问题清单（建议处理）

### 3.1 【已处理·文档】`fuzhan.sample.yaml` 未文档化、但代码已声明且运行的配置节点
以下配置在 `config.go` 已定义、在运行时 `fuzhan.yaml` 中真实存在且被代码使用，但**未出现在 `fuzhan.sample.yaml`**，导致样例文件无法完整还原一份可运行配置：
- `database.pool.max_idle_conns / max_open_conns / conn_max_lifetime`（`database.go`，连接池）。
- `server.jwt_secret`（`config.go`，生成后持久化，样例未声明属预期，建议注释说明）。
- `security.trust_proxy / security.allowed_origins`（CORS 与代理 IP 头；`GetSecurityConfig` 为空来源会默认 `["*"]`）。
- `auth.ldap.*`（enabled/host/port/use_ssl/base_dn/bind_dn/bind_password/user_filter/sync_interval/auto_create_user/insecure_skip_verify）。
- `open_api.*`（enabled/ip_access_mode/ip_whitelist/ip_blacklist/rate_limit_enabled/requests_per_minute/burst_size）。
- `index.search_reconcile_cron_expression`（检索索引对齐 cron，默认 `"0 5 * * *"`）。
- `account.allow_registration`（独立注册开关，与私有存储启用解耦）。
- **处理**：已在 `fuzhan.sample.yaml` 补齐上述全部节点的注释与默认值，样例现为配置的权威清单。

### 3.2 【已处理·界面】设置页未暴露部分后端已有配置项
- `upload.url_upload.enabled / insecure_skip_verify / allowed_ip_ranges`：后端已存在，但 `SettingsView.vue` 模板未提供任何 URL 上传 SSRF 防护的配置控件（数据模型已有，仅缺可视化编辑入口）。
- `index.scan_start_delay_seconds`：后端读取（默认 10s），设置页仅暴露 `scanCronExpression` 与 `searchReconcileCronExpression`，未暴露启动延迟。
- `database.pool.*`、`auth.ldap.*`、`security.*`：后端存在，UI 均无入口（多数属高级配置，可按产品需要决定是否上 UI）。
- **处理**：
  - SettingsBasic.vue「URL 上传配置」新增「允许 IP 网段」文本域（每行一个 CIDR，`allowedIPRanges` 数组 ⇄ 换行文本双向绑定），配合已有的 enabled/insecureSkipVerify 构成完整 SSRF 防护配置入口。
  - SettingsStorage.vue「文件索引配置」新增「扫描启动延迟」数字输入。
  - SettingsView.vue 模型、加载映射、保存体补齐 `scanStartDelaySeconds`；后端 `IndexConfigDTO`/`ToDTO`/`ConfigFromDTO`/保存 handler 补齐 `index.scan_start_delay_seconds` 完整链路。
  - 已在前后端构建通过验证。

### 3.3 【已处理·文档】文档与注释精度
- `log.level` 样例注释写成 `debug, info, warn, error`，而代码支持 `fatal` —— 已补全。
- `download.rate_limit` 的「不支持热开启」注释易误读：实测限流参数 `max_requests`/`lock_after` 每请求实时读取 `appconfig.GetDownloadRateLimit()`，**支持热更新** —— 样例注释现为「关键项为 0/未配置时表示不限制」。
- `database.dsn` 注释建议补充「默认 SQLite 自动落到 `<work_dir>/data/fuzhan.db`」 —— 已补充。
- 代码 `URLUploadConfig.InsecureSkipVerify` 注释写「FTPS/FTP URL」，实际主要用于 HTTPS/FTPS 下载的证书跳过 —— 已统一措辞为「下载 HTTPS/FTPS URL 时是否跳过 TLS 证书验证」。

### 3.4 【已处理·健壮性】`server.host` / `server.tls`
- `server.host` 为空时 HTTP 地址存在退化为空串的隐患：已在 `main.go` 对 HTTP 监听地址做 `0.0.0.0` 回退兜底，与 FTP 侧行为一致。
- `server.tls.cert_file / key_file` 当前明确仅用于 FTPS（`enabled: true` 时强制隐式 TLS）：已在样例注释说明「HTTP/HTTPS 网关未接管，`https.enabled` 需反向代理或另配 HTTPS 服务」。
