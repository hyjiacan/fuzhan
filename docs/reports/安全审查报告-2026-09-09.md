# LightShare 全系统安全审查报告

> 审查日期：2026-09-09
> 审查范围：Go 后端（`server/`，Gin + SQLite）、Vue3 前端（`ui/`，element-plus）、配置文件与默认值
> 审查方式：源码静态审查（人工 + 并行子代理），**未做任何改动、未触碰生产数据**

---

## 一、结论摘要

认证鉴权、路径越界防护、SQL 注入防护、JWT 签名这四类基础安全链路整体做得**较扎实**（详见「四、已正确落实的安全点」）。但存在 **3 个高危、6 个中危** 问题需要优先处理，其中 **Markdown 预览存储型 XSS**、**未认证的 /setup/validate-dir 任意目录创建**、**URL 上传 SSRF 配置默认放行内网** 最为关键。

| 严重性 | 数量 | 代表问题 |
|--------|------|----------|
| 高危 | 3 | Markdown 预览存储型 XSS；/setup/validate-dir 任意目录创建+探测；URL 上传 SSRF 空白名单默认放行内网 |
| 中危 | 6 | 匿名触发全量扫描 DoS；CLI 脚本 Host 注入；分享/临时下载码 32bit 可枚举；uploaderIp 归属判定可伪造；JWT 密钥每次重启失效；匿名注册无法独立关闭 |
| 低危 | 4 | setup 网络接口未认证泄露；(公开)可改备注；admin 路由命名误导；符号链接逃逸(残留) |

> 默认 `server.host: 0.0.0.0`（`fuzhan.sample.yaml:33`）表示服务监听所有网卡，直接放大上述公开接口的暴露面，修复优先级应整体前置。

## 二、高危问题（High）

### H1｜Markdown 预览存储型 XSS
- **位置**：`ui/src/components/file/FilePreview.vue:29`（`v-html="renderedMarkdown"`）、`:143-146`（`renderedMarkdown = marked.parse(textContent)`）；后端 `server/internal/file/preview.go:111` 原样返回文本文件内容。
- **问题**：`marked.parse` 不清理内嵌 HTML（v18 默认无 sanitizer）。任意用户向共享目录上传一个**含 `<img src=x onerror=...>` 或 `<script>` 的 `.md`/`.markdown` 文件**，其他用户预览即触发脚本执行。预览返回文本内容本身也有泄露/污染面。
- **放大因素**：CSP 为 `script-src 'self' 'unsafe-inline' 'unsafe-eval'`（`middleware/auth.go:272`），内联脚本不被拦截。
- **修复建议**：为 `marked` 接入 DOMPurify 白名单清洗后再 `v-html`；同时收紧 CSP（移除 `unsafe-inline/unsafe-eval`，改用 nonce/hash，并收紧 `img-src` 去 `data:`）。

### H2｜未认证的 `/api/v1/setup/validate-dir` 可创建任意目录 + 目录探测 oracle
- **位置**：`server/internal/setup/handler.go:172-221`；路由注册于 `main.go:699-703`（setup 组无任何认证）。
- **问题**：`ValidateDirectory` 未做 `App.Initialized` 门禁（对比同文件 `SaveConfig:70`、`GetDefaultConfig:271` 均有门禁）。攻击者任意提交路径，不存在则服务端执行 `os.MkdirAll(path,0755)`（`:197`）——在服务器任意可写位置**创建目录（越权写）**，并把响应当成「路径是否存在」的探测 oracle `/setup/network/interfaces`（`handler.go:224`）亦可枚举本机非回环 IP 与网卡名。
- **修复建议**：仅在未初始化阶段暴露；对路径做白名单（限定数据目录/用户主目录）；移除自动创建目录能力。

### H3｜URL 上传（SSRF）空白名单默认放行内网，FTP 链路过校验
- **位置**：`server/internal/utils/url_validator.go:64-83`、`server/internal/file/legacy.go:71-90/112-150/410-435`、`file/upload.go` URL 下载。
- **问题**：
  1. `CheckIPSafe` 是**纯白名单**，`Enabled=true` 但 `AllowedIPRanges` 为空时直接放行（`url_validator.go:70`）——`127.0.0.1`、`169.254.169.254`（云元数据）、`::1`、`fe80::` 全部可达；
  2. HTTP/HTTPS 依赖 `DialContext` 的 `Control` 回调做 DNS 重绑定防护（仅禁用时可兜底），但 **FTP/FTPS 的 `ftp.Dial`（`legacy.go:424`）没有控制回调**，校验与连接割裂，存在 DNS 重绑定/二次握手竞态；
  3. `InsecureSkipVerify` 若开启，HTTPS 内容可被中间人篡改。
- **触发前提**：URL 上传功能需在配置开启（默认 `URLUpload.Enabled=false`），开启后即暴露。
- **修复建议**：空白名单应**显式拒绝私网/回环/链路本地**；给 FTP 接入带 `Control` 的 Dialer 并复检实际连接 IP；遍历全部解析 IP 而非仅 `ips[0]`；默认关闭 `InsecureSkipVerify`。

## 三、中危问题（Medium）

### M1｜匿名可反复触发全量索引扫描（资源耗尽 DoS）
- **位置**：`main.go:613-619`——`POST /admin/index/scan`、`POST /admin/index/scan/trigger` 注册在 `scanRoutes`，**位于带 `AuthRequired` 的 admin 组之外**。
- **问题**：`TriggerFullScan` 对全部共享根 + public/temp/private 做遍历与 xxh3 哈希计算（`index/handler.go:100-151`）。匿名者仅受「扫描进行中返回 409」约束，完成后可再次触发，反复造成 CPU/磁盘密集型 DoS。
- **修复建议**：触发类接口加认证或限流。

### M2｜CLI 安装脚本 Host 头注入 shell
- **位置**：`server/internal/cli/install.go:20,39`（`serverURL` 由 `r.Host` 拼成）、`install.go:392-397`（`escapeShellString` 仅转义单引号）；注入点 `SERVER="%s"`（install.go:65）、`fuzhan_SERVER="%s"`（install.go:113）。
- **问题**：`serverURL` 被拼进**双引号**上下文，而转义只处理 `'`。若受害者通过攻击者控制的域名/代理访问本服务（`r.Host` 被诱导为攻击者值），生成的脚本地址会指向攻击者基础设施，且含 `$()`/反引号等字符的 Host 存在命令注入面；脚本本身以 `curl ... | bash` 方式分发，危害被放大。
- **修复建议**：从配置读取服务器地址而非 `r.Host`；对插入值做双引号上下文完整转义或用单引号强引用。

### M3｜分享码 / 临时下载码熵不足且无频率限制
- **位置**：私有分享下载 `server/internal/file/private.go:209-261`（`/share/:code` 免认证）；临时下载 `server/internal/temp/handler.go:242-294`。
- **问题**：均为 **8 位十六进制 = 32bit 熵**，且 `/share` 与 temp `/download` **无频率限制**（登录限流器 `login_limit.go` 只保护 `/auth`）。在 `host:0.0.0.0` 下可被在线暴力枚举到他人私有/临时文件；私有分享还扫全用户目录。另：分片上传会话（temp/私有）仅凭 `uploadId`（32hex）操作、未绑定 IP。
- **修复建议**：分享码改用 128bit 随机值；对 `/share`、temp 下载添加频率限制与失败计数；会话操作绑定创建者 IP。

### M4｜公开文件归属判定 `uploaderIp` 相等，可被伪造头冒充
- **位置**：`server/internal/file/handler.go:255-275`（`canManagePublic`）、`http_utils.go:104-126`（`GetClientIP`）、`main.go:185-191`（TrustProxy 配置）。
- **问题**：删除/重命名/移动公开文件的权限 = 管理员「或上传者 IP == 请求者 IP」。当 `security.trust_proxy=true` 时，`GetClientIP` 直接信任 `X-Forwarded-For`/`X-Real-IP`；若服务可被直接（非经代理）访问，攻击者自造这两个头即可**顶替任意上传者的 IP，管理/删除其公开文件**。即便不信任代理，NAT 后同公网 IP 用户也可互相管理。
- **修复建议**：改为登录用户 UUID/凭证归属而非裸 IP；`trust_proxy` 仅在确实前置可信反向代理且已限定代理来源 IP 时开启。

### M5｜JWT 密钥默认每次重启重新生成（可用性/一致性隐患）
- **位置**：`server/pkg/jwt/jwt.go:53-79`；`fuzhan.sample.yaml:12`（`jwt_secret: ""`）。
- **问题**：无 `JWT_SECRET` 且配置为空时，启动即 `crypto/rand` 生成 32 字节随机密钥（无弱密钥风险，安全），但**每次重启全部已签发 token 立即失效**，多实例/滚动重启不可用；热更新密钥会把旧密钥仅保留 3 份。仅可用性风险，无密码学弱点。
- **修复建议**：初始化/配置时写入固定随机密钥（≥32 字符），不要留空。

### M6｜匿名注册无法独立关闭
- **位置**：`server/internal/services/auth_service.go:62-64`。
- **问题**：注册仅在 `Storage.Private.Enabled` 时允许，**没有独立「允许注册」开关**；要停注册只能整体关私有存储，连带影响登录用户。无邀请码/邮箱门槛。
- **修复建议**：新增独立注册开关配置项（默认随部署策略决定）。

## 四、低危问题（Low）

- **L1｜`/setup/network/interfaces` 未认证泄露内网拓扑**（`setup/handler.go:224`）。建议仅初始化阶段暴露或加认证。
- **L2｜`PUT /files/records/:id/notes` 无认证可改写任意文件备注**（`index/handler.go` 的 `PublicUpdateNotes`）。公开可写的元数据污染面，建议写入操作加认证。
- **L3｜`/admin/search`、`/admin/download` 未认证**（`main.go:604-607`）——实为公开搜索/下载的别名，路径穿越防护完整，**无实质越权**，仅命名具误导性，建议改名或加认证。
- **L4｜共享根内符号链接可指向外部**：`PathValidator.Validate`（`file_utils.go:70-98`）用 `filepath.Abs`（不解析 symlink），根内指向外部路径的 symlink 可通过校验后被读取。属历史遗留残留风险（与项目「共享根必须真实路径」约定相关），低。

## 五、已正确落实的安全点（无需改动）

- **路径越界防护**：下载/预览（`download_service.go:257-271`、`preview.go:52-63`、`file_utils.go` `filepath.Rel` 边界校验）、openapi 下载（DB 键控 + Join）、私有/临时分片目录（`isPathWithinRoot`、`filepath.Clean`+前缀拒绝）、删除目录后 `HasPrefix(abs, root+sep)` 边界判定，整体可靠。
- **JWT**：HS256 算法锁定（`jwt.go:158-164`）、密钥不足 32 字节时拒绝、随机密钥兜底。
- **登录爆破防护**：基于 IP 的滑动窗口限流（5 次/15min → 锁 15min，`login_limit.go`）。
- **证书上传**：`/admin/upload-cert、/upload-key` 在 admin 组内，固定文件名 + 扩展名白名单，无任意文件覆盖。
- **临时文件物理存储**：扁平哈希文件名，`dir` 参数仅用于列表、不参与落盘路径，越界风险极低。
- **SQL 注入**：全库使用 GORM 参数化查询，LIKE 均做转义（`escapeLike`、`listSubdirs` 转义 `%/_`）。
- **下载次数统计**：按请求语义（无 Range / Range 起始为 0）判定新下载，行为一致。
- **安全头**：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`；代理头仅在 `trust_proxy` 开启时采信。

## 六、修复优先级建议

1. **立即（阻断利用）**：H1 为 marked 接 DOMPurify 并收紧 CSP；H2 为 validate-dir 加初始化门禁 + 路径白名单；若 URL 上传在生产开启则优先修 H3。
2. **本周**：M1 扫描触发加认证；M3 分享码/临时下载码加密钥+限流；M4 归属判定改用户凭证；H3 空白名单默认拒内网。
3. **本月**：M2 脚本地址改配置；M5 固定 JWT 密钥；M6 独立注册开关；低危项逐条收敛。

> 说明：本报告基于源码静态审查，未进行动态渗透测试。对于 H1、H3、M3 等可利用性较强的项，建议在**测试环境**用最小 PoC（.md 注入、URL 上传到 `127.0.0.1`、遍历分享码）验证后再上线修复。
